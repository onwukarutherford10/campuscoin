# Hosting the CampusCoin API

Target stack (both free forever, no credit card):

| Piece | Provider | Plan | Notes |
| --- | --- | --- | --- |
| Flask API | [Render](https://render.com/docs/free) | Free web service | 750 free instance-hours/month, sleeps after 15 min idle (~1 min cold start) |
| MySQL 8 | [Aiven](https://aiven.io/free-mysql-database) | Free MySQL | 1 GB storage / 1 GB RAM, may power off after long inactivity |
| Profile photos | [Cloudinary](https://cloudinary.com/pricing) | Free | Direct signed browser uploads and CDN delivery |

Everything the API needs is in this repository: `api/Dockerfile` (image + boot-time
migrations/seed) and `render.yaml` (the Blueprint). You only supply secrets.

> **Hard requirement:** `APP_ENV=production` refuses to start without Brevo
> credentials (`BREVO_API_KEY`, `EMAIL_FROM_ADDRESS`), Cloudinary credentials, and a
> `SECRET_KEY` of at least 32 characters — see `api/app/config.py`. The sender address must be
> verified in Brevo.

---

## 1. Create the free MySQL service (Aiven)

1. Sign up at <https://console.aiven.io> (GitHub/Google, no card).
2. **Create service → MySQL**, plan **Free**, pick a region close to `frankfurt`.
3. Under **Databases**, create/select a database named `campuscoin`.
4. On the service **Overview** copy: host, port, user, password.
5. Download the **project CA certificate** (`.pem`) from the service's
   **Settings → Service members / TLS certificates** page.

Build the connection string (URL-encode the password):

```bash
python -c "from urllib.parse import quote; print(quote('YOUR-DB-PASSWORD', safe=''))"
```

```
mysql+pymysql://avnadmin:<url-encoded-password>@<HOST>:<PORT>/campuscoin?charset=utf8mb4
```

Keep the CA file handy — you will paste it into Render as a **Secret File**.

## 2. Push the repository to GitHub

The repository root must be **this folder** (the one containing `api/`, `src/`
and `render.yaml`):

```bash
cd "campus  cc/campuscoin"
git init -b main
git add .
git commit -m "CampusCoin"
git remote add origin https://github.com/<you>/campuscoin.git
git push -u origin main
```

## 3. Create the Render Blueprint

1. Sign up at <https://render.com> (free, no card).
2. **New → Blueprint → Connect a repository** → pick the repo above.
   Render finds `render.yaml` at the root and previews the `campuscoin-api` service.
3. During creation Render prompts for every `sync: false` variable:

   | Prompt | Value |
   | --- | --- |
   | `DATABASE_URL` | the `mysql+pymysql://…` string from step 1 |
   | `MYSQL_SSL_CA` | `/etc/secrets/aiven-project-ca.pem` (see step 4) |
   | `FRONTEND_ORIGINS` | your frontend origin(s), comma-separated — e.g. `http://localhost:5173,https://campuscoin.netlify.app` |
   | `FRONTEND_BASE_URL` | same origin as the frontend (used in password-reset links) |
   | `BREVO_API_KEY` | the secret transactional API key created in Brevo |
   | `EMAIL_FROM_ADDRESS` | the sender address verified in Brevo, including a verified Gmail address |
   | `EMAIL_FROM_NAME` | `Campus Coin` |
   | `CLOUDINARY_CLOUD_NAME` | the Cloudinary product environment name |
   | `CLOUDINARY_API_KEY` | the Cloudinary API key |
   | `CLOUDINARY_API_SECRET` | the Cloudinary API secret; never expose this to Vercel |
   | `ADMIN_EMAIL` | e.g. `admin@example.com` |

   `SECRET_KEY` is generated by Render — leave it alone.
4. **Before the first deploy**, add the Aiven CA as a secret file:
   service → **Secret Files** → upload the `.pem` → Render mounts it at
   `/etc/secrets/<filename>`. Set `MYSQL_SSL_CA` to that exact path.

## 4. What happens on deploy

`api/Dockerfile` builds a slim Python 3.12 image, installs the package (which
includes `gunicorn`), then the container's `CMD` runs, in order:

```sh
flask --app wsgi:app db upgrade      # Alembic migrations (idempotent)
flask --app wsgi:app seed-categories # category seed (idempotent)
exec gunicorn … wsgi:app             # serve on 0.0.0.0:$PORT
```

Render's pre-deploy command is **paid-only**, which is why migrations run at
boot instead. If you ever need to bypass them, set the service's
**Docker Command** to plain `gunicorn --bind 0.0.0.0:$PORT --workers 2 --threads 4 wsgi:app`.

One-time admin user (run after the first successful deploy, from
**Shell** in the Render dashboard):

```sh
cd api && ADMIN_PASSWORD='<strong-password>' flask --app wsgi:app seed-admin
```

Manual fallback for migrations/seeds, if you disable the boot commands:

```sh
cd api && flask --app wsgi:app db upgrade && flask --app wsgi:app seed-categories
```

## 5. Verify

```bash
curl https://campuscoin-api.onrender.com/health   # {"data":{"status":"healthy"}}
curl https://campuscoin-api.onrender.com/ready    # {"data":{"checks":{"database":"ok"}...}
```

`/ready` reporting `database: ok` means the API can reach Aiven over TLS.

## 6. Point the frontend at it

The Vite dev proxy targets `http://localhost:5000`. For a hosted backend set:

```bash
# .env.production at the frontend's repo root
VITE_API_BASE_URL=https://campuscoin-api.onrender.com
```

and add that URL to `FRONTEND_ORIGINS` (CORS) and `FRONTEND_BASE_URL`.
Host the built frontend (`npm run build` → `dist/`) on Render Static Site,
Netlify or Vite — **HTTPS is required**, because production forces
`COOKIE_SECURE=true`.

## 7. Background jobs

CSV imports and PDF exports that exceed the synchronous row limit queue as
database jobs. Nothing processes them until you run, periodically:

```sh
cd api && flask --app wsgi:app process-csv-imports
cd api && flask --app wsgi:app process-report-exports
```

Render **cron jobs are not free**, so on the free plan run these by hand from
the Shell (or add a paid worker) — small data volumes are unaffected.

## Costs, limits and gotchas

- **Render free**: 750 instance-hours/month (≈ 16 h/day of uptime), sleeps after
  15 minutes without traffic, ~1 minute to wake; 0.1 CPU / 512 MB RAM.
- **Aiven free**: powers off after long inactivity (you get an email first) —
  power it back on in the console.
- **Gmail**: 500 outgoing messages/day per account; use a dedicated account.
- **Cookies**: production runs `SESSION_COOKIE_SECURE=true`; serving the API
  over plain HTTP will break login. Render serves HTTPS automatically.
- Never commit `api/.env` (already gitignored) and never put real secrets in
  `render.yaml` — use `sync: false` / Secret Files.
- `MYSQL_SSL_CA` must point at a file that exists in the container; without it
  the Aiven TLS handshake fails and `/ready` reports `database: down`.

## Alternative: host on your own machine / LAN

No accounts needed — bind Flask to all interfaces:

```bash
cd api
APP_ENV=development FLASK_APP=wsgi:app flask run --host 0.0.0.0 --port 5000
```

Open port 5000 in the Windows firewall, then other devices on your network use
`http://<your-LAN-IP>:5000`. Keep it on `development` unless SMTP is configured.
